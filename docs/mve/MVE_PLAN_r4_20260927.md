## 0. Summary, owner decisions, verdict status

**What we are building.** An engine that lets an AI look at a mathematical picture, write
down what it sees as a typed record with five separate evidence classes (observed,
measured, derived, assumed, judged), decide bounded questions with a small local classifier
that learns from human verdicts, turn explicitly adopted assumptions and a stated goal into a
Lean 4 statement, try to prove it, and render the statement back so a human and the AI look
at the same thing. The human's geometric intuition and the AI's language/Lean fluency meet
at the record.

## 1. Vision

The owner's framing: humans do geometry from the picture; AI does mathematics by language
and now by Lean. The engine makes the picture a shared input. Three consequences:

1. **The record is the product.** A benchmark score is a side effect. The deliverable is a
   record a human can audit line by line and Lean can consume proposition by proposition.
2. **Measure before you trust, and say what was measured.** Checking that a perceiver's
   coordinates are mutually consistent is one thing; locating the geometry in the pixels is
   another. The record names which one happened. The RH visual pilot's lesson stands: every
   blinding hole was found by computing a baseline, not by reasoning.
3. **Level one first.** One road between two houses: plane geometry, a frozen predicate
   registry, synthetic diagrams with exact ground truth, one complete slice
   `image → record → adopted assumptions → statement → proof status → verdict` before any
   predicate expansion, annotation style, solid geometry, knot or atlas panel.

**RH programme link.** Explorer scenes and rhvf panels become records; any visual claim
passes the §9 protocol with its own declared null before it is called a finding; survivors
land in the Evidence Atlas with a statement hash and the actual check statuses. The V0
result (no visual Euler fingerprint beyond spacing) is the standing example of an honest
negative.

### 4a. Evidence model (WP-1, the first thing built)

Five classes, five arrays, never merged. Every item carries `depends_on`; the semantic
validator (`mve/record.py`) builds the dependency graph from that one field and applies
**transitive invalidation** to everything downstream of an edited id, including
`formal.propositions`, `formal.proof` and `formal.render_back`, which also carry
`depends_on`.

| Class | Produced by | Authorises a formal proposition? |
|---|---|---|
| `observations` | perceiver calls; `depends_on` = that call's geometry ids | no; cited only |
| `measurements` | kernel; `method` ∈ {coordinate_consistency, image_measurement, mark_association}; `depends_on` names the exact geometry ids used, so call-1 vs call-2 vs image measurement is explicit | no; cited by an assumption |
| `derivations` | engine on explicit premises (`depends_on` ⊆ prm/ndg/asm ids, never mea); outcome ∈ {proved, counterexample, unknown, unsupported, timeout}; `proved` requires a trace hash, `counterexample` a witness with `exact` true/false and tolerance | yes, `support = derived`, only when outcome = proved and the derivation's target equals the proposition |
| `assumptions` | human, named policy rule, or text; `depends_on` ≥ 1 | yes, `support = assumption` |
| `judgments` | human / model / audit; verdict ∈ {confirm, reject, not_visible, unsure, adopt, decline, label} | **never directly.** `confirm` / `reject` are evidence about visibility; only a human `adopt` judgment creates an assumption (asm_N citing the jud_N), and the assumption authorises. Model judges cannot adopt. `not_visible` and `unsure` are abstention |

**Addressable sources.** A top-level `sources` array holds `txt_N` (kind text: sha of the
full text + character span) and `geo_N` (kind truth_artifact: sha, out-of-band path hint,
generator id / version / config sha / seed / evaluator version / DDAR budget). Problem premises
`prm_N`, nondegeneracy `ndg_N` and the goal `goal_1` each `depends_on` exactly one source id,
so a text edit invalidates them through the graph. `image.ground_truth_ref` and `image.truth.source`
name a `geo_N`. Text-adopted assumptions cite a `txt_N`. `formal.propositions[].depends_on` is
required. The goal enters `formal.propositions` with role `goal` and `support = goal_source`;
it is a source, never an established hypothesis.

**Authorisation table (semantic validator, WP-1):**

| `support` | required `depends_on` and equality check (under the binder→entity mapping, after canonical form) |
|---|---|
| problem_text | exactly one prm/ndg id whose proposition **equals** this one |
| assumption | one asm_N with equal proposition |
| derived | one der_N, outcome proved, target equal |
| goal_source | exactly [goal_1], role goal, proposition equal to `problem.goal.proposition` |

There is no `human_confirmed` support (r3's was removed): confirmation is evidence, adoption
authorises.

**Operations and permitted transitions** (`mve/record.py`, tested with negative fixtures):

| Operation | Actor | Precondition | Effect |
|---|---|---|---|
| create | ingest | image hash | stage ground_truth / ingested, revision 1 |
| perceive | A1 | stage ingested or ground_truth; a re-perceive on a later stage is an edit that invalidates every downstream node first | + observations, + geometries (perceiver_call_k); stage perceived |
| measure | A2 | stage perceived, **or** stage ground_truth for synthetic fixtures (coordinate_consistency on ground_truth geometries, WP-4a); `versions.measurement_contract` set | + measurements, + geometries (image_measurement); stage measured |
| derive | A2c | ≥ 1 premise or assumption | + derivations; stage derived |
| judge | human / model / audit | target exists; `depends_on` includes the target | + judgments |
| adopt | human (via a jud with verdict adopt) or a named policy rule | evidence ids exist and are valid | + assumptions (asm cites the jud or the rule's evidence) |
| decide | A3 | active question, state ≤ 512 tokens | + decisions |
| formalize | A4 | every proposition authorised; goal present for role goal | + formal (emitted → typechecked) |
| prove | A5 | typechecked | + formal.proof; status proved only if ok ∧ sorry_free ∧ statement_matches_accepted ∧ axioms within policy |
| edit | human | any | new revision, `events[].patch` (RFC 6902), transitive invalidation listed in `events[].invalidates` |
| review | Opus / Sol / human | formal.status ∈ {typechecked, proved, counterexample, unsupported} or an explicit negative result | + judgments (question `review`), stage reviewed |
| ingest | A7 | stage reviewed | stage ingested_atlas; record frozen (no further edits; a change is a new lineage record) |

**Stage invariants**: ground_truth / ingested need no perceiver provenance and a null
measurement contract; perceived requires observations and provenance; measured requires the
contract; formalized requires `ir_sha256`, `statement_sha256` and `lean_lock_sha`; proved
requires `typecheck.ok`, `proof.ok`, `sorry_free`, `statement_matches_accepted`,
`dependency_closure_checked` and axioms within policy (schema enforces the booleans;
the semantic validator enforces the axiom policy). These are the same conditions A5 states;
§4a and A5 no longer differ.

**Identity.** `content_hash` is computed over one canonical projection
(`mve/record.py canonical_projection`: sorted-key JSON, no whitespace): for synthetic records
{generator id, version, config sha, seed, registry version, canonical problem, truth candidate
universe sha, exact math-coordinates sha}; for ingested/user records {image sha, registry
version, canonical problem}. **Image bytes are excluded for synthetic records**, so equal seed
⇒ equal `content_hash` whether or not the renderer is pinned; PNG-byte determinism is a separate,
weaker promise that holds only with `image.truth.render_pinned = true`. `record_id` is the
execution identity (content_hash + model + prompt + retained `request_nonce`). Evidence edits
keep `content_hash` and bump `revision`; a problem or truth edit changes `content_hash` and
creates a new record with `lineage.parent_record_id`. `created_at` is execution metadata.

**Validation authority.** `schemas/mve_observation_record.json` (v4) is authoritative; the
`docs/mve/` copy is derived and checked equal in CI. JSON Schema enforces structure and the
conditional rules (an observation of kind proposition needs a proposition; `unmeasurable`
has a null residual while `consistent` requires residual, **unit** and tolerance; `proved`
requires `typecheck.ok`, `proof.ok`, `sorry_free`, `statement_matches_accepted`,
`dependency_closure_checked` and non-null statement / IR hashes; a counterexample witness
has at least one coordinate; edits require a patch; formal artifacts carry ids `tc_1`,
`prf_1`, `eqv_1`, `rnd_1` with `depends_on`). **Dependency graph**: nodes = sources, problem
propositions, entities and geometries, obs, mea, der, asm, jud, dec, prop, tc, prf, eqv, rnd;
mandatory edges: prm/ndg/goal → src; entity → the prm/ndg/goal ids naming it; geometry
(ground_truth) → geo_N; obs → its call's geometries; mea → geometries used + obs; der →
prm/ndg/asm; asm → evidence; jud → target; dec → state inputs; prop → its authorising node;
tc → props; prf → tc; eqv → tc; rnd → tc. **Conflicts**: optimistic concurrency, an edit
whose `from_revision` is not current is rejected, never merged; the editor rebases. Invalidated
nodes get `valid = false` and cannot be cited by any new node. The semantic validator enforces uniqueness
of ids across arrays, referential integrity, authorisation, stage invariants and transitive
invalidation. Older schema versions are rejected, not migrated (nothing was produced under
them).

**Predicate registry v1, frozen P1 rows** (argument roles, symmetry group used for the
canonical form = lexicographically minimal argument order under the group, repeated-point
policy: any repeated point makes the candidate `degenerate` and excludes it from the
universe unless stated; Mathlib target):

| Predicate | Args (roles) | Symmetry | Degeneracy | Mathlib |
|---|---|---|---|---|
| Collinear(A,B,C) | three points | S3 | — | `Collinear ℝ {A,B,C}` |
| Concyclic(A,B,C,D) | four points | S4 | any three collinear → degenerate | `Concyclic {A,B,C,D}` |
| Parallel(A,B,C,D) | line AB ∥ line CD | swap within a pair; swap pairs | A=B or C=D → degenerate | `line[ℝ,A,B] ∥ line[ℝ,C,D]` |
| Perpendicular(A,B,C,D) | AB ⟂ CD | same as Parallel | same | `⟂` on the two lines |
| EqualLength(A,B,C,D) | dist A B = dist C D | swap within pair; swap pairs | — | `dist A B = dist C D` |
| EqualAngle(A,B,C,D,E,F) | ∠ABC = ∠DEF, vertex in the middle | swap A↔C; swap D↔F; swap triples | A=B, B=C, D=E, E=F → degenerate | `∠ A B C = ∠ D E F` |
| Midpoint(M,A,B) | M is the midpoint of AB | swap A↔B | A=B → degenerate | `M = midpoint ℝ A B` |
| SBetween(B,A,C) | B strictly between A and C | swap A↔C | any equal → degenerate | `Sbtw ℝ A B C` |
| RightAngle(A,B,C) | ∠ABC = 90°, vertex B | swap A↔C | A=B or B=C → degenerate | `∠ A B C = π/2` |
| Distinct(A,B) | nondegeneracy | S2 | — | `A ≠ B` |
| NotCollinear(A,B,C) | nondegeneracy | S3 | — | `¬ Collinear ℝ {A,B,C}` |

**Incidence mapping** (restored from r2): Geoperception's `PointLiesOnLine(P, line AB)` is
`Collinear(P,A,B)` with nondegeneracy `Distinct(A,B)`; `PointLiesOnCircle` is inactive in P1
(Concyclic with the circle's three defining points is the P2 candidate). Angles undirected
in degrees; circle `[cx,cy,r]`; line vs segment by entity kind. Exact values: the grammar in
schema `$defs.exact` (integers, rationals, `sqrt(n)`, `pi`, `+ - * / ^`), parsed by the
semantic validator with sympy, canonical string via `nsimplify`, domain real algebraic;
anything else is rejected. Binders typed {Point, Line, Circle, Real, Nat}. All other
predicates are registered but inactive.

**Problem contract**: `problem.texts` (addressable), `binders`, `premises`, `nondegeneracy`
(Distinct / NotCollinear only), `goal` (kind, proposition, source) or null → the formalizer
emits an assumption record and no theorem.

**Tracks and tasks**: `image.track` ∈ {appearance_only, annotated_problem} and
`image.eval_task` ∈ {appearance, annotation_reading, problem_understanding}; the two fields
are independent so the three scored tasks are discriminated explicitly.

**Input isolation** (`image.isolation`): visible to inference stages = printed labels,
stated givens and problem text on the annotated track; hidden always = generator premises,
truth classes, consequences, answers, reference paths. Ground-truth artifacts are stored out
of band and never mounted for A1–A3.

### A0 Ingest
Sources as r1. OCR runs once per `annotated_problem` image, stored with its coordinate
frame. `ground_truth_ref` and any reference path are held outside the inference process
(separate directory, never mounted for perception, measurement or classification).

### A1 Perceiver
DeepSeek V4.1 Flash, **two calls per image, both charged**, temperature 0, no chain of
thought, JSON only. Coordinates for every entity kind per the registry (circles `[cx,cy,r]`,
marks `[x,y,w,h]`, crossings `[x,y]`). Entity alignment between the two calls by geometry
(Hungarian on normalised coordinates, threshold in the measurement contract); agreement is
an instability signal, not verification. Malformed JSON, refusal, out-of-image coordinates
and missing entities are recorded as such; retries bounded (2); raw responses retained.

### A2 Measurer
- **a) Coordinate consistency**: recompute each perceived relation from the perceiver's own
  coordinates under the JSXGraph measurement contract. A consistent set of hallucinated
  coordinates passes this; the record says so (`method = coordinate_consistency`).
- **b) Independent image measurement**: locate points, segments and circles in the pixels
  (edge/Hough on the appearance-only render; marks by template match), then recompute the
  relation from those coordinates (`method = image_measurement`). This is the measurement
  that can contradict the perceiver.
- **c) Mark association**: which entities a tick / arc / arrow belongs to, with the OCR
  evidence; precedence rule when a drawn dimension disagrees with an annotation
  (`annotated_problem`: annotation wins and the disagreement is an event).
- **Derivation**: Newclid on explicit premises only; outcomes as in 4a; trace stored.
  `.ggb` / JGEX export is UNVERIFIED until the WP-4 preflight runs it.

### A3 Router
Order: code → openJev → LLM → human. Exhaustive routing table in `mve/questions/routing.json`:
for each question, `act` if c > τ_high; `llm` if τ_low < c ≤ τ_high; `human` if c ≤ τ_low,
or abstained, or evidence missing, or the question is `disabled` (support floor unmet).
Boundaries therefore belong to the lower route, consistently. Confidence is the selected-label
probability unless the lock file names another statistic.

### A4 Formalizer
Record → **MVE formalization IR** (binders, premises with evidence refs, goal, exact
constants, nondegeneracy) → **native Mathlib** statement for the supported subset, with a
LeanGeo adapter where LeanGeo's semantics match and its tactics help. Unsupported
predicates fail closed. Statement typecheck and proof check are separate artifacts;
typechecking a statement never requires a fabricated proof. Repair (≤ 3 rounds) may fix
syntax, names and binder order only; any change to the proposition's meaning is a
formalization failure and is logged as such.

### A5 Prover
Counterexample search first (Newclid numeric model over the registry's coordinate domain,
30 s budget, witness = coordinates plus `exact` flag: a witness is `exact` only when
validated in rational/algebraic arithmetic, otherwise it is numeric within a declared
tolerance and reported as such; "none found" is `unknown`). Axiom policy
`mathlib_standard_only` (propext, Classical.choice, Quot.sound); anything else fails. Then the prover with a 120 s search budget under
declared hardware, quantization, decoding, attempt counts, model revisions (HF commit), a
repair allocation (0 in G4a) and a timeout that includes model load and Lean check. "Proved" means: Lean accepted
it in a trusted environment, `sorry_free`, axioms listed, dependency closure checked, and
the theorem text is byte-identical to the accepted statement.

### A6 Co-observer surface
Four panes plus an assumptions pane. Verdict events: `confirm`, `reject`, `not_visible`,
`unsure` on observations and measurements; `adopt` / `decline` create or refuse assumptions
(schema judgment verdicts include both); human id on
every event; conflicting edits resolved by revision, never overwritten; downstream
invalidation as in 4a. Render-back is a supported-subset renderer (Penrose Euclidean
domain, JSXGraph) with a semantic round-trip test (render → measure → compare with the IR);
`render_back.realizations` ∈ {one, multiple, none, unsupported} is explicit.

### A7 Ledger
Aggregate cap across waves with reserved in-flight cost, retries and both perception calls;
API-dollar and account-quota calls accounted separately; `DEPS.lock`; stop precedence:
mechanical failure or zero measurements stops immediately (no classifier involved); the
classifier's asymmetric STOP applies only to content decisions; restart authority is Opus.

## 5. Classifier layer (openJev) — routing and workflow questions only

Root question from the infographics: *do you know every possible answer before you ask?*
Applied honestly:

| Question | Route |
|---|---|
| Is C on line AB? cyclic quadrilateral? angle value? genus? knot type? | **code** (measurement / invariants) with uncertainty; never the classifier |
| Which domain / track / workflow / solver / reviewer? | **openJev Choice** |
| Does this free-text claim restate a measured relation, add a new one, or contradict one? | **openJev Choice** (workflow: what to do with the claim) |
| Has the goal drifted from the problem text? | **openJev Noul** as a *flag for review*, never as a semantic verdict |
| Does this step follow? is this statement equivalent? explain why | **LLM / Lean / reviewer** |

The classifier's finite answer list prevents arbitrary output strings; it does not prevent
false answers. Every catalogue entry has: id, primitive, labels, a separate **abstention**
option (not a label; Score and Noul get `abstain` as a distinct output), a state template,
the complete-input token count measured at runtime (question + labels + delimiters + special
tokens, limit 512, truncation forbidden: over-limit → abstain), τ_high / τ_low, and an
**activation stage**.

| id | primitive | labels | activates | target label source |
|---|---|---|---|---|
| Q-domain | Choice | euclidean_plane, solid, function_plot, chart, graph, knot, surface, braid, unsupported | P2 | synthetic truth + human |
| Q-track | Choice | appearance_only, annotated_problem | P2 | ingest metadata |
| Q-shape | Choice | triangle, quadrilateral, circle, polygon_n, line_config, mixed | P2 | synthetic truth; exclusivity: the label is the single closed figure with the most vertices (n ≥ 5 → polygon_n); no closed figure → line_config; ≥ 2 closed figures or a circle plus a polygon → mixed |

### 5a. Recursive self-learning loop (D1)

1. **Decide** with the current lock; record everything (§4 decisions).
2. **Label** from two sources kept separate: human verdicts (weight 1.0) and manager
   judgments (DeepSeek V4-Pro text or Opus, weight 0.5, judge id recorded) on items routed
   `llm`/`human` and on the audit sample. Human wins on conflict; the conflict is an event.
   Each question's **target label** is defined in the catalogue: a relation confirm/reject
   click labels nothing in the catalogue (it is visibility evidence); Q-claim-workflow is
   labelled only by its own four buttons on a free-text claim (§5).
3. **Split three ways by diagram / construction family**: training, calibration (thresholds
   and refit acceptance), evaluation (untouched, replaced after any result influences
   development). Alternate renderings of one construction never straddle splits.
4. **Refit** the openJev head when floors are met. **The training pipeline does not exist
   yet**: WP-5 first runs a spike proving a checkpoint, trainable parameters, objective,
   weighting, ONNX export and inference parity on a fixture; until then "refit" means
   threshold refit only.
5. **Promote or roll back** on the calibration set: no per-question drop in selective
   accuracy at fixed coverage (unanswered / abstained items count as not-covered, never as
   correct), 95% intervals reported, human-queue rate reported (a rise can be correct under
   more uncertainty; it is reported, not forbidden). New lock with labelled-set sha256,
   weights sha256, wave id, metrics; every record names the weights that decided it.
6. **Audit**: one reproducible 10% sample per wave (seeded) from the declared population
   "decisions routed `act` in this wave", adjudicated by a judge other than the manager
   whose labels are being compared; the wave summary reports sample size, population size
   and any stratum with zero coverage (sampling-bias line); audit outcomes are labels.

Never: learn from unaudited confident answers; move a threshold by hand; let Opus's labels be
the gold for measuring Opus.

## 9. Evaluation and honesty protocol (r2)

1. **Declared null or N/A.** Stochastic classification gets its computed chance for the
   exact sample; structural validity, elaboration and proof checks get "N/A".
2. **Isolation, not just sealing.** Hidden ground truth (generator premises, truth classes,
   answers, reference paths) lives outside the inference process; stated givens and problem
   text on the annotated track are legitimate inputs and stay visible (`image.isolation`); HMAC filenames alone do not isolate gold. Prompt
   development, tolerance fitting, retrieval, calibration and evaluation use disjoint,
   family-split data; an evaluation set that influenced development is retired.
3. **Controls every wave**: exact positives, adversarial negatives, near-miss negatives,
   weakened / strengthened statements, unchanged-record round trips.
4. **Two calls, one arbiter**: disagreement is instability evidence; agreement is not
   verification.
5. **Tracks apart**: appearance-only, annotation reading and full problem understanding are
   three tasks with three answer keys.
6. **Stop precedence**: mechanical failures stop immediately; the classifier's asymmetric
   STOP governs content routes only; 10% audit of confident answers.
7. **Name the check**: "typechecks", "kernel-accepted with axioms […]", "Sol-judged at
   level 3", "numerically consistent, derivability unresolved". Never "verified" alone.

## 12. Open questions, answered (per Astra, adopted)

- **IR vs Lean-typed fields.** The canonical representation is the typed,
  language-independent record (schema v4). A small formalization IR (binders, premises with
  evidence refs, goal, constants, nondegeneracy) sits between the record and Lean. Lean
  strings are derived outputs, never the meaning of a relation. MechGeo's GeoIR is cited as
  the pattern; its implementation is not adopted.
- **Target dialect.** Native Mathlib for the initial plane-geometry subset via an MVE adapter
  that fixes conventions; a LeanGeo adapter for its reference tasks and tactics where
  semantics match. One pinned toolchain set in an isolated project; unsupported predicates
  return `unsupported`.
- **Equivalence scoring.** Four evidence levels, reported apart, never collapsed:
  structural agreement under an explicit variable mapping; machine-supported correspondence
  with artifacts; blinded reviewer-judged agreement with identity and rationale; unknown /
  unsupported kept in the denominator. Whole-theorem logical equivalence is too coarse;
  weakened, strengthened, vacuous and unrelated-but-provable controls are mandatory.
- **First topology statement.** For a validated PD record D, the arc-successor relation
  obtained by following strands through crossings (never joining over and under strands) has
  exactly one component. It is a certificate about the decoded combinatorial record; the link
  to the picture (transcription) and to a topological link (interpretation) are separate
  arguments and are not implied. P5 may legitimately end at validated PD and invariant
  records; unknot recognition, genus and equivalence are not prerequisites.
