## Implemented and exercised

`mve/budget.py` owns a SQLite campaign ledger. All waves must use the same file.
Atomic write transactions count settled actual costs plus every reserved or dispatched
ceiling against the aggregate USD 20 and phase P0 USD 2 / P1 USD 8 caps. P3 is refused.
Thread and independent-process races cannot reserve the same remaining capacity twice.
Retries require new attempt ids; a dispatch permit is single-use. A killed process leaves
its dispatched reservation charged until an explicit receipt reconciles it. Unsent
reservations alone may be cancelled. Actual overcharges are retained and freeze dispatch.

Peak-window checks run after acquiring the transaction lock, both at reservation and
dispatch intent. The exact borrowed policy is pinned in configuration, UTC weekdays
01:00–04:00 and 06:00–10:00 refused, weekends allowed. **UNVERIFIED against vendor terms.**
The original runner remains unchanged; its two WP-0a findings remain valid. The fake
USD .04 + .04 against .05 counterexample is refused by this new ledger.

Mechanical failure, zero measurements and operator stop freeze the campaign without a
classifier. Only the declared Opus role can restart; unresolved dispatched attempts or
exposure above a cap prevent restart. Stop, resume and accounting-breach events persist.
Account quota units are recorded separately from API dollars.

`mve/pricing.py` normalizes pinned rate/source-hash/verification metadata and computes
upward-rounded ceilings from input/output token bounds. Rates in persisted configuration
are integer micro-USD per million tokens; input rates supplied to the constructor are
USD per million. Configuration changes on reopening are refused. Fixture rates are
explicitly unverified. `mve/money.py` converts decimal amounts without context rounding.

## Review boundaries and next integration obligations

This is an offline accounting primitive, not a hosted-call launch authorization. WP-11a,
reviewed integration, actual vendor/window verification and a guarded transport are still
required. A future adapter must authenticate the operator, use the single campaign path,
provide true upper bounds including image/hidden tokens, check the window at actual send,
dispatch once per permit, and reconcile authenticated provider receipts. An `actor='Opus'`
string or receipt hash alone does not authenticate either source. Fixture clock injection
is for offline tests. A delayed transport must not reuse a stale off-peak timestamp.
No inference can start merely because this module accepts a reservation.

SQLite transactions serialize cooperative clients; a user who edits/deletes the database
or supplies a different campaign file can bypass accounting. Price verification metadata
is provenance, not an access-control credential. A vendor charge above a declared bound
cannot be prevented retrospectively; it is retained, surfaced and stops subsequent work.
The operational adapter must detect mechanical failure/zero measurements and call stop;
this library does not observe a model runner automatically.

WP-0 and WP-1 are separate pushed review branches. On reviewed integration, union their
DEPS.lock entries and retain their tests; this branch is deliberately based on r5 rather
than stacking unreviewed work. Shared wiki refresh tooling is absent from this integration
base, so this durable handoff lives under docs/mve instead of generated wiki output.
