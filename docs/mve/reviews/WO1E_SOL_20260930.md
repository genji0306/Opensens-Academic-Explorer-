# WO-1e recapture admission and failed-attempt recovery

## Finding and fix

The WO-6c snapshot IDs derive from module and source, so the 16 IDs repeat across capture plans. The old quarantine reader treated an active directory with the same ID and no `complete.json` as superseded evidence. During the first worker recapture, the four new snapshot directories were in progress and admission refused them. The reader now requires the active native attempt's sealed plan and matching receipt to identify the current plan. A snapshot recapture also requires a matching batch claim and fresh bytes. It still checks the complete 20-move superseded record, every moved directory and file hash, and the quarantined artifact set.

The failed attempt recovery writes a sealed `mve-wo6c-failed-attempt-quarantine-v1` record before moving the failed native attempt and any partial snapshots of its batch. It accepts only a sealed `plan.json` with a matching `receipt.json` whose status is `failed`. It refuses captured or accepted attempts and completed snapshots. The reader verifies the record and the moved files on every admission. No quarantined file is deleted or overwritten. A worker exception now leaves `worker-traceback.txt` in the attempt directory, with exception type, a message only for fixed safe diagnostics, and bounded stack locations. The parent `traceback.txt` remains separate.

The real WO-6c evidence was **read only**. In a temporary copy, the actual failed `native/0` (plan `604055543b648fdcbe01f7c627df5d811a4d4d9e26545e10022724e1815760e9`) was set aside and admitted, and four in-progress same-ID recapture directories admitted under the current plan. Fix 1 correctly refuses the still-active failed attempt before set-aside. The real WO-1b evidence was **read only**. In a temporary copy, the 66 active completions admitted; copying the four IDs from `partial-spectral-contrast-2-153` back into active snapshots admitted 70 completions while retaining the quarantine record. The WO-1b manifest hash `d286a45abc8187fd06bd63a1957d34c809ca0c82abaf9aad8485ef3b9abe7620` did not change.

## Fix 1

The independent review blocked WO-1e because a receipt could override a superseded sealed plan, an unfinished snapshot could claim the wrong batch or reuse quarantined bytes, and worker tracebacks could expose arbitrary messages. Adversarial tests reproduced these failures first. Admission now requires both active attempt hashes to agree with the current plan; snapshot claims must come from the selected batch and contain no file bytes copied from that ID's quarantined inventory. The native parent writes a failed-status receipt before launching the worker, then atomically replaces it with the final receipt. Failed-attempt recovery verifies all quarantines after moving its targeted failed attempt, allowing the real `60405554…` attempt to be set aside without admitting it as current. Tracebacks redact unlisted messages as `<redacted>` and retain only exception type, stack locations, fixed safe diagnostics, or an OS error code.

The final focused WO-1d/WO-1e run passed **95 tests**. The full offline `tests/mve` run with the four named nested-sandbox-only tests deselected passed **1,349 tests**, skipped 8, and deselected 4; the final symlink regression passed separately. Changed executable production lines reached **90.32%** coverage (56/62) with the Python tracer. No browser or network was used. The Fix 1 WO-6c plan hash is `6735e51c5bc2b44789483c7996f27c2aff4405fd98effd65172fd64ba439f8e5`.
