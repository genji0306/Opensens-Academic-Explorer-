## Credential and response handling

The only credential subprocess is `/usr/bin/security find-generic-password -s oae-deepseek-api-key -w`, captured in memory with a 10-second timeout. Its result never goes to stdout, files, logs, another process's argv, or refusal exception context. It is invoked only after approval, image/price validation, reservation and persistence. A missing key cancels the unsent reservation but still consumes the one-shot ID.

Transport uses stdlib urllib, TLS certificate verification, the fixed `https://api.deepseek.com/chat/completions` endpoint, a 30-second socket timeout and one request. This is a socket timeout, not a guarantee of a whole-exchange wall-clock deadline against a server continuously trickling bytes. Responses are bounded at 1 MiB plus one sentinel byte; oversize responses fail with that captured prefix. Authorization is redacted in receipts. A credential echoed by the server is replaced before any raw bytes are saved, with `raw_redacted: true`; otherwise the captured bytes are unchanged.

`mve/generated/wp0b-live/probe/` holds `request.json`, `image.png`, `response.raw`, `receipt.json` and `ledger.json`. Raw bytes are written before parsing. The receipt contains requested/returned model IDs, HTTP status, usage including optional image/cache details, latency, raw hash, image acceptance, pinned prices, review commit and reservation. `image_accepted` describes API acceptance, not accurate image understanding; it is unknown when the response does not establish acceptance.

There is no vendor billing field. Valid matching-model usage produces `cost_basis: derived_from_usage`, using the pinned peak cache-miss/output rates as a conservative upper estimate, without assuming cache discounts. This is never labelled vendor-billed. Unknown usage, malformed transport bodies, HTTP errors and timeouts settle the failed attempt at the full retained reservation with `cost_basis: reservation_retained_unknown_cost`; that amount is conservative ledger exposure, not an observed charge. Model mismatches preserve usage but remain unpriced and freeze the ledger. Process loss before settlement leaves the durable reservation in place. All these states prevent another attempt after restart. Do not delete the ledger or generate a new attempt ID to retry.
